# ZFinance Backend — Coding Standards

Python + FastAPI backend for AI-powered financial dashboard. This document establishes development norms for code quality, structure, and consistency.

## Quick Start

**Run the server:**
```bash
uvicorn main:app --reload --port 8000
```

**Run tests:**
```bash
python test.py
```

**Project structure:**
- `main.py` — FastAPI application entrypoint, CORS setup, router registration
- `rag/engine.py` — Core RAG orchestration (ChromaDB, embeddings, LLM integration)
- `rag/routes.py` — API endpoints (ingest, narrative, health-score, ask, anomalies)
- `rag/chunker.py` — Financial data chunking and preparation
- `rag/anomaly.py` — Statistical anomaly detection
- `rag/prompts.py` — LLM system/user prompt templates
- `data/` — Sample CSV files for testing and development
- `chroma_db/` — ChromaDB storage (persistent)
- `test.py` — Integration tests for RAG endpoints

## Dependencies

- **Runtime:** FastAPI, Uvicorn, pandas, numpy, chromadb, sentence-transformers, groq
- **Configuration:** python-dotenv (for environment variables)
- **Testing:** requests (for HTTP testing)
- **Optional:** mypy (type checking), black (formatting), pytest (unit testing)

## Code Quality Standards

### Type Hints (Required)

All function signatures must include type hints. No bare `def func(...):`.

✓ **Good:**
```python
def ingest_csv(df: pd.DataFrame, business_id: str, week: str) -> int:
    """Ingest CSV data into ChromaDB.
    
    Args:
        df: Input dataframe with 'date' and 'amount' columns
        business_id: Unique business identifier
        week: Week identifier (e.g., "week1")
        
    Returns:
        Number of chunks stored
    """
```

✗ **Bad:**
```python
def ingest_csv(df, business_id, week):
    return n
```

**Union types:** Use `Type1 | Type2` (Python 3.10+) instead of `Union[Type1, Type2]`.

```python
def fetch_data(week: str | None = None) -> dict | None:
```

### Docstrings (Required)

All functions and classes must have docstrings. Use Google-style format.

```python
def generate_narrative(self, business_id: str, week: str) -> str:
    """Generate AI narrative for a business's financial data.
    
    Retrieves relevant chunks from ChromaDB, sends to LLM, returns narrative.
    
    Args:
        business_id: Unique business identifier
        week: Week identifier matching ingested data
        
    Returns:
        Narrative text generated by LLM
        
    Raises:
        ValueError: If business_id or week not found in database
    """
```

For simple one-liners, a single-line docstring is OK:
```python
def health() -> dict:
    """Return API health status."""
```

### Error Handling (Required)

Use FastAPI's `HTTPException` for API errors. Always provide a status code and descriptive message.

✓ **Good:**
```python
from fastapi import HTTPException

if not file.filename.endswith(".csv"):
    raise HTTPException(
        status_code=400,
        detail="Only CSV files are supported. Got: " + file.filename
    )

try:
    df = pd.read_csv(io.BytesIO(contents))
except Exception as e:
    raise HTTPException(
        status_code=422,
        detail=f"Could not parse CSV: {str(e)}"
    )
```

✗ **Bad:**
```python
if not file.filename.endswith(".csv"):
    raise Exception("Wrong file type")  # No status code
```

**Logging:** Use Python's `logging` module for debug/info messages, not `print()`.

```python
import logging
log = logging.getLogger("zfinance.rag")

log.info(f"Ingesting {len(df)} rows for business {business_id}")
log.error(f"LLM call failed: {e}")
```

### Imports (Required)

1. **Order:** stdlib, third-party, local imports (separated by blank lines)
2. **Alphabetical:** Within each group, sort alphabetically

✓ **Good:**
```python
import io
import json
import logging
import os

import chromadb
import numpy as np
import pandas as pd
from chromadb.utils.embedding_functions import SentenceTransformerEmbeddingFunction

from rag.anomaly import detect_anomalies
from rag.chunker import build_financial_chunks
from rag.prompts import NARRATIVE_SYSTEM
```

✗ **Bad:**
```python
import os
from rag.prompts import NARRATIVE_SYSTEM
import pandas as pd
import io
```

### Naming Conventions

- **Functions/variables:** `snake_case` (Python standard)
- **Classes:** `PascalCase` (Python standard)
- **Constants:** `UPPER_SNAKE_CASE` (Python standard)
- **Private methods:** Prefix with `_` (e.g., `_call_llm()`)

✓ **Good:**
```python
class ZFinanceRAG:
    TOP_K = 10
    
    def generate_narrative(self):
        pass
    
    def _call_llm(self):
        pass
```

### Pydantic Models (Required for API)

All request/response types must be Pydantic models. Use type hints and optional fields with defaults.

```python
from pydantic import BaseModel

class NarrativeRequest(BaseModel):
    business_id: str
    week: str

class AskRequest(BaseModel):
    business_id: str
    question: str
    week: str | None = None  # Optional field

class NarrativeResponse(BaseModel):
    business_id: str
    week: str
    narrative: str
```

### Code Organization

1. **One responsibility per file:** `engine.py` handles RAG; `routes.py` handles API endpoints
2. **Constants at top:** Environment variables, config values (see `engine.py` example)
3. **Class-based state:** Use `ZFinanceRAG()` class to manage ChromaDB connection and LLM provider state
4. **Avoid side effects:** Functions should not modify global state unexpectedly

## API Design

### Endpoint Patterns

- `POST /api/rag/ingest` — Ingest CSV data
- `POST /api/rag/narrative` — Generate narrative
- `POST /api/rag/health-score` — Calculate health score
- `POST /api/rag/ask` — Q&A endpoint
- `GET /api/rag/anomalies/{business_id}/{week}` — Detect anomalies
- `GET /api/rag/weeks/{business_id}` — List available weeks
- `DELETE /api/rag/weeks/{business_id}` — Clean up data

### Response Format

All responses must be JSON-serializable. Use consistent structure:

```python
return {
    "business_id": business_id,
    "week": week,
    "result": value,  # or "narrative", "score", etc.
}
```

### Status Codes

- `200` — Success
- `400` — Bad request (validation error)
- `422` — Unprocessable entity (parsing error)
- `500` — Server error

## Environment Variables

Store configuration in `.env` (use `.env.example` as template). Never hardcode secrets or paths.

```bash
# .env
CHROMA_PATH=./chroma_db
EMBED_MODEL=all-MiniLM-L6-v2
LLM_PROVIDER=groq          # "groq" | "ollama"
LLM_MODEL=llama3-8b-8192
GROQ_API_KEY=gsk_...
RAG_TOP_K=10
ANOMALY_SIGMA=2.5
```

Access with:
```python
import os
from dotenv import load_dotenv

load_dotenv()
GROQ_API_KEY = os.getenv("GROQ_API_KEY", "")
```

## Testing

### Test File Pattern

Write tests in `test.py` using the `requests` library:

```python
import requests

BASE_URL = "http://localhost:8000"

def test_health():
    resp = requests.get(f"{BASE_URL}/health")
    assert resp.status_code == 200
    assert resp.json()["status"] == "ok"

def test_ingest_csv():
    # Set up CSV data
    files = {"file": ("data.csv", open("data/sample.csv", "rb"))}
    params = {"business_id": "test_biz", "week": "week1"}
    
    resp = requests.post(f"{BASE_URL}/api/rag/ingest", files=files, params=params)
    assert resp.status_code == 200
    assert "chunks_stored" in resp.json()
```

**Run tests:**
```bash
python test.py
# or
pytest test.py -v
```

## CORS & Security

- **CORS:** Configured in `main.py`; update `allow_origins` for production (no `*`)
- **Input validation:** Always validate file extensions, CSV structure, dataframe shape
- **Error messages:** Don't leak internal paths or stack traces to clients; log them instead
- **Secrets:** Never commit `.env` or API keys; use `.env.example` as template

## Logging

Use `logging` module, not `print()`:

```python
import logging

log = logging.getLogger("zfinance.rag")

log.debug("Debug details (won't show by default)")
log.info(f"Processing {len(df)} rows")
log.warning("Unexpected data format")
log.error(f"Failed to generate narrative: {e}")
```

Enable debug logging in development:
```python
logging.basicConfig(level=logging.DEBUG)
```

## Code Review Checklist

When submitting a PR, verify:

- [ ] All functions have type hints
- [ ] All functions/classes have docstrings (Google format)
- [ ] Error handling uses `HTTPException` with meaningful messages
- [ ] Imports are ordered (stdlib, third-party, local) and alphabetical
- [ ] Environment variables are in `.env`; secrets never hardcoded
- [ ] New endpoints use Pydantic request/response models
- [ ] Logging uses `logging` module, not `print()`
- [ ] Tests pass: `python test.py`
- [ ] Code style: runs `black` and passes `mypy` (if configured)
